# 0798. Time zones and clock formats in the client

## Status

Accepted

## Context

A daily quiet time names a zone of the IANA time zone database, and the server holds it while the clock of that zone shows a time inside the window (ADR 0412). A client must offer the zone of the system as the first choice and a list of zones to choose from, and it applies the rule of the quiet time to what it holds by the clock of the zone (ADR 0792). The client core holds no time zone data: its function takes the minute of the day from its caller. macOS and Linux have the database as files; Windows has none.

## Decision

- The window crate has one module for zones: every name of the database in the order of the alphabet, a search of the names, the name of the zone of the system, and the minute of the day that the clock of a named zone shows at an instant.
- The names and the rules come from the crate `chrono-tz`, which carries the database in the binary. The list is the same on the three systems and does not depend on a file of the system. The crate uses `chrono`, which the window has for the times of messages.
- The zone of the system is the zone that the variable `TZ` states, and otherwise the name from the crate `iana-time-zone`. `TZ` is read in the forms of the C library, after an optional `:`: a name of the database; the path of a file of the database (`/usr/share/zoneinfo/Europe/Lisbon`), whose name is the part after `zoneinfo/`; or the path of a link to such a file (`/etc/localtime`), which is followed once. A rule in the form of POSIX (`<-03>3`) names no zone of the database; the client then uses the zone that the system states, and a test of the module checks each form. A system that states no name, or a name that the build does not hold, gives `UTC`.
- The application reads the zone of the system once at the start, before the first window is drawn, and again on a background thread each time the main or detached call window becomes active: a person who changes the zone of the system does it in another application. The reading asks files of the system (`/etc/localtime`), so the thread of the window does not read it after the start (ADR 0730); the settings of the window show the zone that was read last.
- The times of messages, notices and searches are shown by the rules of `chrono-tz` for that zone. `chrono::Local` is not used: it reads `/etc/localtime` on the thread that asks, at most once a second. The `clippy.toml` of the window crate refuses the type `chrono::Local`, `chrono::Local::now`, `chrono::Local::today`, `iana_time_zone::get_timezone`, the local offset functions of `time` and the zone functions of the module. Clippy does not refuse `chrono::Local` used as a value, so a test reads the tokens of the code of the crate and fails on every identifier `Local`; a text or a comment that contains the word does not count (ADR 0730).
- A name that the build does not hold gives no clock, and so no quiet time, as an unknown zone does on the server.
- The search ignores case and takes a space for the underscore of a name. Names whose last part starts with the typed text come first. A search returns at most 50 names and states that more exist.
- The server decides with its own database whether it accepts a name. A name of the list that the server refuses is stated as a refusal of the request.

Clock format:

- Interface offers System, 12-hour and 24-hour. System is the default. An optional `clock_format` field in the existing versioned installation settings keeps the choice; old files default to System. A resolved hour cycle belongs to the application state and is passed through the pure view/feed/recording sources. There is no mutable process-global display format, so independent test contexts cannot change one another's times.
- The core's clock module formats the time of day, with seconds where the existing display has them. Twelve-hour times use 1 through 12 with AM or PM; midnight is 12 AM and noon 12 PM. Twenty-four-hour times use 00 through 23. The existing dates, zones and explicit UTC labels are kept. Message, thread, reply, recording and system rows, notices, search results, transcript changes, account/device/recovery/link times, administrative lists and audit detail, recording failures and call reconnection text all receive the resolved cycle. The system-line timestamp column keeps its 40-pixel minimum and grows to fit AM/PM, so it cannot paint into the following status mark.
- macOS reads Foundation's localized `j` template with the current locale, which chooses the preferred hour cycle ([Date Formatters](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/DataFormatting/Articles/dfDateFormatting10_4.html)). Windows reads the current user's short-time pattern with [GetLocaleInfoEx](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getlocaleinfoex), including user overrides. Linux reads the [GNOME clock-format preference](https://github.com/GNOME/gsettings-desktop-schemas/blob/master/schemas/org.gnome.desktop.interface.gschema.xml.in) on GNOME and Budgie, then the current LC_TIME `t_fmt` on other desktops or if that preference is unavailable. The locale command resolves the environment without changing the Rust process's global locale. Each external read uses a fixed system-program path, a one-second process deadline and at most 4 KiB of output. An unavailable or unknown pattern falls back to 24 hours.
- The native cycle is read at startup and then refreshed with the zone on a background worker when either window becomes active. The existing generation number rejects an older combined result. The explicit 12-hour or 24-hour choice keeps taking precedence. The window thread uses the cached value; clippy refuses a direct native preference read there. Tests inject the reader and pin their initial fake system cycle, independently of the machine's personal preferences.
- Daily quiet-hour fields initially use the selected cycle. They accept both 24-hour text and AM/PM, including midnight/noon, and send the same minutes of the day to the server. A changed cycle reformats pristine fields; an unfinished typed edit is preserved. Dates without times, elapsed durations, protocol/CLI forms, logs, panic filenames and sortable recording file stems keep their own formats because they are not times of day being displayed as a clock.

## Consequences

- The database of a build is the one of its release of `chrono-tz`. A zone whose rules changed afterwards has the old clock in the client until a new build, while the server uses its own database. A test sets a quiet time in several zones against the real server and checks that the server holds a notice back at the minute that the client computed.
- The binary grows by the tables of the database.
- The settings of the window offer the zone of the stored quiet time, or the zone of the system, and a search of the names to choose another one (ADR 0742). The window applies a quiet time by the clock of the zone that the settings name.
