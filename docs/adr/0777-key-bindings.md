# 0777. The key bindings of the person

## Status

Accepted

## Context

Junto had a key to quit, the key of push to talk of the sound settings (ADR 0507) and the key that mutes (ADR 0776); every other action needed the pointer or a menu. Discord's Keybinds list lets a person give each action a key combination, with defaults, also for actions that work while another application is in front, such as the mute key. Slack and Teams list keyboard shortcuts for moving between workspaces, channels and unread channels, for search and for marking read.

## Decision

The actions (`keybinds::KeyAction`), each with a default where Discord has the action (the actions of the window use Command on macOS where they use Control elsewhere; the actions of a call use Control and Shift on every system, as Discord):

- Call: mute or unmute (Control+Shift+M), turn the sound off or on (Control+Shift+D), push to talk (held; the key of the sound settings while the person sets no other), push to mute (held; no default), turn the camera on or off (Control+Shift+E), share a screen or a window (Control+Shift+S, the dialog of a share), leave the call (Control+Shift+H), answer and decline a call that rings (Control+Enter, Control+Shift+Backspace; the first ringing call), show the call (Control+Alt+A), open or close the panel of the call (Control+Shift+P; the action `toggle_call_panel`: in the call window and in a narrow main window the panel over the content, in a wide main window the panel beside the stage, which opening the panel at one of its tabs shows again), as the button of the header does, with the one state of the panel that the settings keep beside the stage (ADR 0730).
- Navigation: back and forward through the places that the window showed (Alt+Left and Alt+Right, Command+[ and Command+] on macOS, as Discord and Slack), previous and next server (Control+Alt+Up and Down), workspace (Control+Shift+Up and Down), channel (Alt+Up and Down), unread channel (Alt+Shift+Up and Down), collapse or expand the server book (Control+Shift+B), search (Control+F), quick switcher (Control+K), notices (Control+I), jump to the newest message (Shift+Page Down), members (Control+U), pinned messages (Control+P; a second press closes them, as the button of the header does). A step goes around the end of its list.
- Messages: mark the channel as read (Shift+Escape; Escape closes menus and dialogs in Junto), mark the server as read (Control+Shift+Escape), reply to the newest message (Control+Shift+R), edit the last own message (Control+Up, Command+Up on macOS, as Slack; it does nothing while the composer holds a draft, so a draft is not replaced), upload a file (Control+Shift+U), the direct messages (Control+Shift+K, as Slack: the newest conversation of the shown server), a new direct message (Control+N). Up in an empty composer also edits the last own message, through the same path.
- Junto: settings (Control+Comma), administration (Control+Shift+Comma), the Keybinds section (Control+Slash), zoom in (Control+=), zoom out (Control+-) and reset zoom (Control+0), with Command instead of Control on macOS (ADR 0731). Quit stays the key of the system (Command+Q, Control+Q) and is not a binding.
- The list is the one registry of the actions of Junto that a key does: a later action joins it with its default. The quick switcher now owns Command or Control with K as an ordinary configurable action; no application keys are reserved for a future action.
- Back and Forward: the window state keeps the places that it showed (a server with its workspace and its channel, or a direct conversation), at most 50 in each direction; a new place after Back forgets what Forward held.

The bindings (`keybinds::Keybinds`):

- A binding has its keys or none, and for an action of a call (mute, sound off, push to talk, push to mute, camera, share, leave, answer, decline, show the call) whether it also works while another application is in front. Share and show the call need a window: a press from outside brings Junto to the front and the main window does the action (the state sends it the event `WindowKeyAction`). The panel of the call and the actions of the window work only while Junto is in front. Mute, sound off, push to talk and push to mute work outside by default, as in Discord; the others while the person switches it on.
- Keys are modifiers and at most one other key: a letter, a digit, F1 to F24, an arrow, Enter, Escape, Backspace, Page Up, Page Down, comma, slash, =, -, [ or ]. The keys of an action that happens at a press need a modifier, so that typing does not do it; the keys of a held action can be one key.
- The settings file of the interface keeps the bindings that differ from the defaults, by the name of the action (format 3; a file of format 1 has none, every action has its default). A file whose binding breaks these rules is read without that binding. A change is written under the lock of the data directory with only that change, so that a second program keeps its other changes (ADR 0710).
- The key that mutes of ADR 0776 is this binding: the sound settings stay at format 4 and have no key that mutes. Push to talk keeps the key of the sound settings (Alt or Control, ADR 0507) until the person sets another one; its reset returns to that key. The binding stores inheritance separately from an explicitly removed key, so changing only the outside switch keeps the inherited key. Format 2 push-to-talk overrides with no keys migrate to inheritance; format 2 could not keep an explicit removal with the default outside switch.
- Two actions with the same keys are a conflict, which both rows state; a press does the first of them in the order of the list. The polling reader and portal remove the other equal bindings before dispatch or registration, preserving the order of distinct bindings.

In the window:

- Every window of Junto, the main window and the call window, reads its key presses before the focused element (`capture_key_down`): a press whose keys are a binding does its action and goes no further. A binding that the keyboard of the system reads now is not done a second time by the window.
- While a window records keys, no binding does its action, in any window or from the keyboard of the system: the recording releases the holds of push to talk and push to mute, the Wayland portal ignores its presses, and the keys that are held at the end of the recording do nothing. After the recording, the keyboard of the system gives events again only after it has read no key held (on Wayland at once, since the desktop gives a press only at its start), so the press that was recorded does not do its new action.
- Push to talk and push to mute hold while the window holds their keys: the modifiers and the last key that went down and not up. Deactivation clears both holds and the cached keys; destroying a window releases both of its holds.
- The settings have a section "Keybinds": how the keys reach Junto on this system (ADR 0776, with the permission of macOS), "Reset all", and for each group and action its keys with "Set" (the next keys that the person presses; Escape stops; refused keys are stated and the wait goes on; another section or closing the settings stops it), "Remove", "Reset" while it differs from its default, the switch "Also while another application is in front" for an action that may, and the conflict. The Voice section points to it.

Outside the window: the keyboard of the system (ADR 0776) reads the bindings that work outside while this device is in a call, and answer and decline while a call rings; push to talk only while push to talk is on. A Wayland desktop gets one shortcut per binding through its portal, named by the action. When the held keys hold two bound combinations and one holds the other, only the larger one is a press, and a press counts when its own combination becomes held.

Tests: `keybinds::tests` (defaults without conflicts, the standard quick-switcher combination, change, conflict, reset, the modifier rule, the actions that may work outside, the file form), `settings::tests::a_file_of_version_1_has_the_default_bindings_and_each_change_keeps_the_other_part`, `global_keys::tests` (presses and holds of several bindings, the larger combination), `global_keys::portal::tests`, on Windows `global_keys::windows::tests::a_binding_of_a_modifier_and_an_arrow_is_one_press` (Control and Up pressed through `SendInput`), and the window tests `keybinds::a_binding_is_recorded_its_conflict_shown_and_reset_and_a_second_start_keeps_it`, `keybinds::a_binding_does_its_action_while_the_window_is_in_front`, `keybinds::a_call_binding_works_from_the_keyboard_of_the_system_when_it_may_work_outside`, `keybinds::back_forward_and_the_direct_messages_at_their_keys`, `keybinds::recording_a_binding_suppresses_global_actions_until_the_recording_press_is_released`, `keybinds::the_navigation_and_message_actions_at_their_keys`, `keybinds::the_keys_of_the_shown_channel_mark_it_read_jump_to_the_newest_and_upload` (the read mark here and on the server, the newest message, and the file dialog of the composer), `keybinds::share_from_the_keyboard_of_the_system_opens_the_share_dialog` and `calls::the_keys_of_a_call_reach_the_call_from_the_source_and_from_the_window`.
- A binding goes before the keys that the focused element binds to its own actions: each window reads every keystroke before gpui matches the actions of the focused element (`intercept_keystrokes`), performs the action of a binding there and stops the keystroke. The text fields of the component library bind some default keys of the bindings (Command and the arrow up on macOS moves to the start of the text, Control and F opens the search of a text area on Linux and Windows, Alt, Shift and an arrow adds a cursor on Linux), as Discord and Slack give their own keys the first place. Held keys and the recording of a binding stay with the key-down listener of the window. Test: `keybinds::a_binding_goes_before_the_keys_of_the_focused_composer`.

Quick switcher:

- Command+K on macOS and Control+K elsewhere opens a dialog above the current screen, also while a text field is focused. It is the configurable `quick_switcher` navigation action. Escape restores that screen and its focused control, without discarding a draft or an unfinished settings field. Choosing a destination closes the previous layer and uses the existing navigation or direct-conversation flow; choosing a voice channel does not join its call. In the detached call window a choice brings the main window forward.
- The directory includes all saved servers by name/address, every visible text and voice channel of every joined workspace, and existing direct conversations on every authenticated server. Collapsing a server, workspace or category does not hide its destinations. It reads only the permission-filtered model of the account of the current session. Server and workspace labels distinguish equal names across origins. A missing conversation name can be supplied by the current permitted contact result.
- Each open switcher resolves the counterpart profiles of its retained direct conversations, including background servers and departed accounts. The profile API applies its existing historical-account permission rule. Name entries are scoped by server entry generation, owning account and counterpart, and retained only while the current snapshots contain those conversations and the dialog is open. At most two profile reads run at once, sharing the four-read window budget with contact search. Responses check the dialog opening, request generation and current owner; invalidation cancels names as well as contacts. Temporary failures expose explicit retry; inaccessible profiles remain plain unavailable names. These name-only records hold no avatars and do not depend on the selected workspace or an earlier warm people cache.
- A typed query also asks the contacts route of every authenticated server (ADR 0307), including permitted accounts outside visible member lists. The shared contact-search state keeps one request per server, pages, a maximum of 500 contacts per server, a new wanted part after an outstanding request, explicit retry after failure, and opening/account guards. The switcher permits four outstanding reads per window. Retained tasks cancel when the dialog closes, reopens or loses that server/account. A monotonically increasing opening number rejects an obsolete answer. Permission, membership, profile, account and server-role events, or a replaced snapshot, invalidate that server’s contact cache and give its new reads another generation; an older completion cannot cancel the replacement read. The main and call windows keep independent queries. Empty text offers existing destinations without starting a directory-wide people request.
- Matching ignores case and requires every typed word in the name or its origin label. Unread destinations precede read destinations, then names and origins sort alphabetically with identifiers breaking ties. A matching existing conversation replaces the same person's contact result. The list shows at most 500 matches and asks for more text when that bound is reached. Contact pagination offers further people within its per-server bound.
- Up and Down move the selected destination and reveal its row. Enter opens it; a pointer press uses the same handler. Destination identifiers, rather than row indexes, own the controls, so an answer that reorders the list cannot change what a pending press selects. Selection rechecks the current session's directory. The existing server route decides whether a new conversation is still allowed. Loading, empty and failure/retry states stay within the bounded result area; input, footer and rows keep their positions as answers arrive.

Tests: `state::switcher::tests` checks word/origin matching and unread order; the shared `state::contacts::tests` checks sequencing and stale openings. `tests/app/switcher.rs` checks focus and unfinished-field restoration, duplicate channel names across two servers, unread order, arrow/Enter and pointer navigation, permitted contact lookup, conversation deduplication, interrupted queries, retry, two independent windows, and logout rejecting a previously offered destination.

## Consequences

- A person can give every action of the list a key, and the call actions also work while another application is in front where the system lets Junto read the keys (ADR 0776).
- The actions of the window work while a window of Junto is in front only.
- A binding of the window can take keys that a field also uses, such as Alt+Up in the composer; the binding takes them.

The native menu equivalents for Settings and zoom mirror the current bindings of that registry. Loading, changing, removing or resetting those bindings replaces only their menu-action bindings while preserving the input library's and window's other bindings, then refreshes the native bar. An action with a conflicting combination shows no equivalent unless it is the first action for those keys. The Shell interceptor consumes a bound press before it reaches the menu action, so a key acts once; clicking the menu uses the same Shell action. Removing a binding also removes the native equivalent, so it cannot continue to fire through a second path.
